# 未対応事項と変更方針

設計レビューで扱った、現行実装との差や追加検証を記録する。実装済みの機能一覧ではない。`proposed` の ADR は今後の方針であり、その挙動を現行 API の保証として利用しない。

## CPU と GPU の範囲判定

現在は float32 の列値に対し、GPU は float32 の閾値、CPU ホバーは丸め前の閾値を使う。GPU フィルターの近似精度を明記することとは別に、同じ範囲条件が CPU と GPU でずれる問題を修正する。

変更時は、float32 の丸め境界をまたぐ値、min/max の省略、条件の更新で判定を確認する。SQL と同じ精度へ引き上げることは今回の方針に含めない（[データ契約](data-contract.md)）。

## ポインターのホバー対象

[ADR-0005](adr/0005-hover-targets.md) の方針へ変更する。描画された灰色の不一致点も対象とし、LOD で間引いた点は対象外にする。ID 指定では引き続き全点を扱い、点本体を強制描画しない。

確認する場面は、通常表示、`grayed`、LOD による間引き、パン・ズーム、範囲条件の変更。ラベルが 0 件・非表示の場合にアウトラインまで描画されない現行の依存も、合わせて検討する。実際の描画集合とホバー対象の整合を取る方法は、実装時の検討事項とする。

## 初期化失敗の通知

[ADR-0006](adr/0006-initialization-failures.md) は破壊的変更を伴うリリースに向けた提案。現在のイベント購読例を、実装前に新しい契約の利用例へ置き換えない。

WebGPU の準備失敗、必須データの取得・クエリ・検証失敗では初期化の Promise が reject され、警告だけなら処理を続けられることを確認する。既存利用者向けの移行説明も必要となる。

## 入力の検証

座標と GPU フィルター値に対して、列の存在・数値型・NULL・NaN・Infinity・float32 変換後の非有限値を明示的に検査する処理は未実装。合意した入力条件は [データ契約](data-contract.md) を参照。

無効な行を黙って削除すると点 ID の対応を変えるため、その場での除外を既定動作にしない。初期化時の無効データは明示的に失敗させる方針とする。公開 API での通知の統一は ADR-0006 と合わせて扱う。

## 性能の基準

数十万〜数百万点を主対象とする方針に対して、端末・データ・操作を揃えた測定結果がまだない。[開発手順](development.md) の条件と計測の限界を添えて基準を記録し、対応範囲の説明へ反映する。

## 実行時依存の宣言

`@duckdb/duckdb-wasm` は実行時に import するが、現在の `package.json` では `devDependencies` にしか含まれず、`dependencies` は空。TypeScript のビルドも依存をバンドルしないため、利用側で別途インストールが必要となる。README には現在の回避手順を記載し、配布側で実行時依存を宣言する修正を別途行う。

## LOD ピラミッドの再検討

[過去の提案](lod-pyramid-design.md)には、現行の binding 配置、サイズ優先 LOD、選択・ホバー強調を強制描画しない判断との不整合がある。実装する場合は冒頭の差分を解消して再評価する。今回のレビューはピラミッド方式の採用を承認するものではない。

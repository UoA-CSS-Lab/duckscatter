# 初期化を継続できない失敗は Promise の reject で通知する

初期化を継続できない失敗は `initialize()` の Promise を reject し、設定の無視や任意ラベルの読み込み失敗など、続行できる警告はイベントで通知する方式へ移行する。イベントだけで致命的失敗も通知する方式に比べ、`await` した呼び出し元が成功と失敗を直接区別できることを優先する。無効な必須数値を検証して見つけた場合も、黙って行を除去せず初期化の失敗として扱う。

## 互換性と現在の通知

破壊的変更を伴うリリースに向けた未実装の提案であり、現在の API 保証ではない。現在は致命的な初期化エラーでもイベントを発行して Promise が解決するため、利用側は初期化前に `error` を購読する必要がある。初期化中の全点クエリ失敗では `QUERY_FAILED` を通知し、空データで処理が進む経路もある。`runQuery()` の SQL 失敗は現在も reject される。

移行時は、イベントのみを購読する既存コードへ `try/catch` を追加する必要がある。必須データの読み込み・検証・描画準備のいずれかが失敗した場合、成功したように Promise が解決しないことを確認する。

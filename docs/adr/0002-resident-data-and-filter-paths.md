# 全点を常駐させ、SQL と GPU にフィルター処理を分担する

全データへの SQL と、頻繁な範囲変更に対する応答を両立させるため、DuckDB-WASM に全データ、GPU に全点の描画属性を保持する構成を維持する。複雑な条件や色・サイズの計算は SQL、頻繁に変える数値範囲条件と描画は GPU が担当し、SQL 条件は点 ID に対応する一致ビットマップとして描画へ渡す。

タイル取得やストリーミングによる初期負荷の削減よりも、全件に対する問い合わせと再取得なしの操作を優先する。その代わり、初期読み込みと CPU・GPU のメモリ使用量は全件数に依存し、描画予算を下げるだけでは軽くならない。将来、タイルで GPU の走査範囲を絞る最適化を検討しても、データ自体を部分取得する設計への移行とは区別する。

`runQuery()` は SQL をそのまま実行する低レベルの窓口とし、表示中の条件を自動適用しない。集計・一覧と表示条件の同期は利用側が明示的に行う。任意 SQL で行集合を書き換えた際の描画キャッシュ同期は保証しない。

GPU の数値範囲条件は float32 の近似として扱い、精密な判定は SQL に任せる。日時など桁の大きい値は利用側で基準値からの差分へ変換する。SQL・CPU・GPU の境界判定が完全に同じ精度になる保証は設けないが、CPU と GPU で丸め方が異なる現行の不整合は解消対象とする（[データ契約](../data-contract.md)）。

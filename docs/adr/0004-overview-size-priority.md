# 俯瞰はサイズの重要度を優先し、ズームインでは分布を保つ

俯瞰では `sizeSql` の大きさを探索上の重要度として扱い、大きい点を優先して残す現行の LOD を維持する。一様なサンプルによる分布の代表性よりも、重要な点が間引かれないことを優先する。同サイズの場合は `rowid` 順になるため、入力の並びによって俯瞰に偏りが出る性質も、この方式の制約として受け入れる。

サイズ順位を使うのは `zoom <= 1` の俯瞰時だけとする。全体順位をズームインした部分領域へ適用すると、小さい点の領域が消え、大きい点の領域では過描画になるため、`zoom > 1` では PCG ハッシュへ切り替えて局所的な分布を保つ（実装と採用理由の履歴: `787ff37`）。描画予算は保持率を決める目標値であり、厳密な件数上限は設けない。

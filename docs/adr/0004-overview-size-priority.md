# 俯瞰はサイズの重要度を優先し、ズームインでは分布を保つ

俯瞰では `sizeSql` の大きさを探索上の重要度として扱い、大きい点を優先して残す。一様なサンプルによる分布の代表性よりも、重要な点が間引かれないことを優先する。

2026 年 11 月 3 日の変更では、点ごとの順位配列をサイズ別の累積件数に置き換える。CPU で保持率に対応する境界サイズを求め、GPU には境界サイズと同サイズ用のハッシュ閾値だけを渡す。境界より大きい点を残し、同サイズは `rowid` の固定 PCG ハッシュで間引く。従来の `rowid` 順の優先をやめ、均一サイズでは一様なハッシュ間引きにする。サイズの比較と集計の同値判定は GPU と同じ float32 に揃える。分布は CPU に保持し、点ごとの LOD 用 GPU バッファは作らない。

サイズ優先は `zoom <= 1` の俯瞰時だけとする。全体のサイズ分布をズームインした部分領域へ適用すると、小さい点の領域が消え、大きい点の領域では過描画になるため、`zoom > 1` では PCG ハッシュへ切り替えて局所的な分布を保つ（従来の実装と採用理由の履歴: `787ff37`）。保持率は [ADR-0007](0007-render-time-target.md) の時間目標から自動調整し、厳密な件数上限は設けない。
